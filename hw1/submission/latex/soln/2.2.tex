Please see the generated plots in Figure~\ref{fig:bicycle_xy} and
Figure~\ref{fig:bicycle_state}. The main gap in this model is the no-slip,
pure-rolling approximation. If this model were to hold, we would see $v_y =
l_rr$ for the entirety of the trajectory. This would mean there is not slip
occurring in the true, force-based model. Plotting to see if $v_y = l_rr$ holds
in Figure~\ref{fig:bicycle_slip}, we can see that at the beginning of the
trajectory (where the heading error is large), this no-slip condition is in fact
violated. This induces tracking error because the true heading is different from
what the controller intends, causing drift in position.
